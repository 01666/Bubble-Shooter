# 验证与发布

## 开发环境

运行游戏无需npm安装；Node.js和game/目录即可。开发时在game/中执行npm ci，依照package-lock安装Prettier 3.6.2、playwright-core 1.62.1。游戏使用捆绑Babylon.js 9.30.0，不经CDN加载。

这台电脑捆绑Node.js但PATH中没有npm命令，整理时从官方npm注册表下载锁定包并核验SHA-512完整性，开发工具已可使用。其他标准Node.js环境直接npm ci。未验证这台电脑上的npm ci命令，因为没有npm可执行文件。

```powershell
cd game
node tools/check.mjs
node --test tests/core/*.test.mjs
node tools/test-browser.cjs
# 有npm的标准环境
npm run check
npm test
npm run test:browser
npm run format:check
```

测试依赖本机Chrome/Edge。必要时设置BROWSER_PATH为浏览器程序路径。helper先使用本地playwright-core，找不到时尝试本机Codex捆绑库。测试不安装浏览器，不使用用户当前浏览器的配置文件。

| 验证                | 覆盖                                                                       |
| ------------------- | -------------------------------------------------------------------------- |
| tools/check         | 活跃代码语法、相对模块存在、旧目录依赖排查、主要离线资源                   |

| clearance.test      | 固定方向连续90发，炮台安全线、维护、核心守恒                               |
| browser/integration | 真实按键、投币10球、音频32文件、卡票、刷新、核销、暂停、重复音乐解锁、窄屏 |
| browser/loader      | 免费不取下一球、付费沿曲线装填、颜色一致、只扣1球、恢复预览、新机器随机    |
| browser/guide       | 渐淡渐小、隐藏落点、静止稳定、真实弹道一致                                 |

integration和loader自动启动临时服务4225/4226，使用独立浏览器存储，随后关闭。guide和vfx使用默认4210服务，但同样创建独立浏览器上下文。图像和报告输出在output/verification/v1.0/，与源码分开。

输入测试以游戏逻辑时钟等待按键持续时间，避免无头浏览器帧率波动导致误判。随机盘面不要求固定24发一定集满3颗星，阶段完成逻辑由可重复核心测试验证。

## 本次验证与限制

本次整理已运行核心12项、50种子随机性检查、90发安全线检查，以及完整浏览器集成和装填检查。具体最终结果见09整理记录与output/verification/v1.0。

这些是桌面浏览器软件验证；没有Android板卡帧率、真实出票成功率、实物断电回执、商用长程回报或玩家试测结论。声音加载和单实例检查通过不等于柜体扬声器声压已调校。

## 发布纪律

1. 每次明确修改目标，改源码后先跑对应检查；涉及核心/账务时跑全部核心测试。
2. 每次发布明确工程版本、规则配置版本、存档schema、资源清单和迁移策略。
3. 保存本次报告和代表性截图，区分已执行检查与计划检查。
4. 发布包包含game、docs、根README和启动脚本；排除node_modules、历史archive和临时日志。
5. manifest记录实际文件大小与SHA-256，用于核对基线。真实设备升级还需签名、授权、持久备份和回滚，当前未实现。

发布包脚本：game/tools/package-release.ps1。它只在output/releases下创建新目录，保留之前的同版本包，不清除用户存档。1.0基线的资源清单位于output/releases/v1.0.0/manifest.json。

任何已运营机台的参数和版本更新，都不应靠删除localStorage来“升级”。正式Android包应关闭测试入口和开发控制台，并增加可靠存储与硬件适配。
