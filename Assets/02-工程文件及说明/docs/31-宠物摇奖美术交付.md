# 宠物摇奖与连续消除：表现模块交付

日期：2026-10-13。基于当前蓝金遗迹街机画面，新增可独立接入的表现层。游戏概率、奖励、锁定发射、出票和持久化均由核心负责，本模块仅呈现已提交事件。

## 设计与布局

- 延续当前 `ArcadeDisplay` 字体、青铜机关外壳、蓝色能量与金色奖励，所有奖项图标为代码绘制，无 emoji、远程字体或图片依赖。
- 左下原助攻提示位置改为“萌宠蓄力 X/3”及“成功消除蓄力 · 满3格摇奖”。满格摇奖期间显示3格点亮。位置 `49,1230`，大小 `248×76`；额外三颗菱形能量在 `y=1215`。
- 连消提示位于 `450,1110`：连续消除、强力连消、狂热连消三档，显示连续次数。升级播放不同音高的短提示，失误后核心 streak 归零自然消失。已经获得的奖不受表现层影响。
- 摇奖时才展开 `278,914`，`490×278` 的机关面板，在盘面前方、发射器上方，保留左右上额度与底部炮口。外壳有金属渐变、嵌边、铆钉和三只蓝色转轮。不会使用大型全屏灰罩。
- 三轮使用连续加速和减速的平滑积分，逐轮停到实际奖励图标。停轮依次时间为总时长减0.72/0.48/0.24秒。最后一轮停止后保持结果，等待核心真正发出开奖事件，绝不由浏览器计时开奖。
- 拉杆随开场约0.55秒动作下拉回位，已有宠物骨骼 pose 叠加右臂、侧望、轻跳、翅膀及开奖欢呼。没有改动宠物头身定位或重绘宠物模型。
- 揭晓显示“实际奖项标题＋真实数量/单位”。结果1.65秒退场，末0.25秒淡出。每次摇奖必有奖由核心保证；画面不制作“差一点中另一个奖”的伪结果。

## 奖项表现

| 核心 rewardType | 机关图标 | 揭晓与实际结果表现 |
| --- | --- | --- |
| tickets | 有齿线的立体金票 | 彩票 +实际到账张数；金色场景脉冲 |
| lightning | 蓝白立体闪电 | 闪电消除实际颗数；沿已提交 `electricPaths` 绘制蓝色外光、白色内芯连锁闪电；实际消失点扩散光环 |
| specials | 带引线的橙金球 | 特殊泡泡 +实际加入颗数；仅在 `added` 对应位置发出扩散圈与粒子 |

| dual | 蓝紫两颗立体球 | 下一发获得双彩助攻；保留旧模块对已装填双彩球的绘制 |

特效点位都来自核心结果，不随机画虚构的获奖球。粒子受低画质24点/中高画质96点限制，每点最多4颗粒子，同时最多4组结果特效。减少动态时保持奖项、进度和真实命中位置，移除转轮滚动、弹跳、随机电弧锯齿及粒子，不用频闪传达奖励。

## 文件与接口

入口：`game/src/feedback/pet-slots/index.mjs` 导出 `PetSlotFeedback`。

- `art.mjs`：机关外壳、奖项图标、统一字体绘制。
- `feedback.mjs`：事件去重、演出状态、倒计时同步、音效、实际结果特效及宠物 pose。
- `game/tests/feedback/pet-slots.test.mjs`：6个独立测试。

构造：`new PetSlotFeedback({ audio, room, mapPoint })`。

`mapPoint(ball)` 将核心球坐标映射到900×1600逻辑画布，与 `scene.renderedPoint` 保持一致。它也会接收无 id 的闪电路径端点 `{x,y}`。`audio.playCue(name,options)` 使用已有声音；静音由音频系统控制。`room.consume(events,snapshot)` 只收取带独立 eventId 的表现事件，绝不回写游戏。

生命周期：

1. `restore(snapshot)` 恢复存档。若正在摇奖，依据 `remaining` 继续显示；不重播开场、转轮提示音或历史结果。
2. `consume(batch,snapshot)` 接收 `comboChanged`、`petChargeChanged`、`petSlotStarted`、`petSlotResolved`。
3. `update(dt,snapshot,{paused,reduced,quality,priorityBusy})` 同步时间。暂停冻结结果退场与粒子，核心 remaining 为摇奖权威时间。
4. `draw(ctx,snapshot)` 绘制，`petPose(pose,pet)` 叠加已有宠物动作。
5. `stats()` 返回 `active/spinning/revealing/spinId/elapsed/effects/cues/reduced/seen`。`dispose()` 退场并禁用新反馈。

`active` 与 `busy` 只在摇奖或结果展示时为 true；普通蓄力/连消不会抑制其他通知。`suppressCombo` 可由宿主设为 `!!words.active || stages.length>0`，避免静态连消和旧奖励文字在同一区域叠加。`priorityBusy` 为故障/存储异常等高优先级状态，不应由“可发射球数为零”触发，否则最后一球蓄满无法看到奖励。

## 宿主整合注意事项

旧 `MechanismRenderer` 增加 `petSlotEnabled` 属性。宿主设为 `snapshot.petSlots?.mode==='slots'`（核心没有 `enabled` 字段）时仅隐藏旧固定三格蓄力与“满3格送双彩”，仍保留真正中奖后的下一发双彩说明和球体表现。`mode:'legacy'` 存档保留旧UI，本模块不绘制三格，仍可显示连消。连消显示“狂热连消 · 4连”，不用乘号暗示彩票倍率。

开奖 active 时，应暂停旧 stage 通知排队、隐藏旧 RewardWords/宠物气泡/免费提示，避免多句叠加。消失后恢复排队。核心中奖闪电还发出 `networkPropagated`，其 `payload.rewardSource==='petSlots'` 应从旧电网特效输入过滤，因为本模块已呈现同一真实 electricPaths；不要让两个系统重复画相同闪电。其余普通导电网事件照常保留。

本模块不增加系统TTS，也不宣称已有真人语音。奖励目前使用已有短音效并同步文字；后续真人录音可在开奖事件处独立接入。

运行 `node --test game/tests/feedback/pet-slots.test.mjs`：6项通过。

覆盖：同一事件及换 eventId 的同一 spin 结果去重；只读 snapshot；暂停与退场；减少动态仍可读；中途刷新静默继续并且完成奖励不重播；真实闪电路径/新增球点位；连消不会误触发全局 active；所有六奖项在不依赖 canvas 素材和声音时均可绘制。
