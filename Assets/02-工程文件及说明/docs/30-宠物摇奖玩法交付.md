# 连续消除与宠物摇奖核心交付

## 目的和体验边界

本次把两种目标分开：连续消除奖励连续的操作表现，宠物三格提供可累积的期待。连续消除失误会断连；宠物蓄力失误不损失。中奖结果均有真实玩法或账务效果，动画不决定中奖，也不依赖视觉回调确认奖励。

普通付费射击落地、实际 direct 数大于零计一次成功。一次炸弹或闪电链条无论包含多少段只计一次成功。连消 2 / 3 / 4+ 对应 tier 1 / 2 / 3，单次及无连消为 tier 0。本版不叠彩票倍率，仅提供 tier 作为演出输入。免费试玩、退款、补球、暂停、刷新不增加或中断连消；中奖奖励触发的清除不计新一发，也不赠大消除奖励球。

## 宠物三格

每次成功付费射击增加一格，第三格满后自动摇奖，2.6 秒后一次性结算。不要求连续成功，未消除不丢格。旧已 ready / inFlight 双彩权益仍然兑现，中奖双彩作为后续的一种奖项保留；旧固定三格入口在新模式关闭。旧 charging 存档剩余格数迁入 petSlots，旧 assist 清零。新字段增量迁移，不修改原 config 默认值，因此 1.6.1 配置匹配和存档继续可读。

老虎机演出期间：core.fire 返回 false；顶部推波计时冻结、球盘不变。投币与实际出票确认仍允许，瞄准也仍允许。推进由 advance(dt) 的有效帧时间驱动，dt=0 不推进，后台大 dt 仍受现有 maxFrameSeconds 限制。

## 原型奖池

| 结果 | 权重 | 实际效果 |
| --- | --- | --- |
| tickets | 30% | 8–16 张彩票，整数均匀；写入已有出票账本 |
| lightning | 20% | 从盘面真实邻接球出发，随机行走，最多 4–7 颗，任何颜色；若无足够邻居可提前结束，但至少 2 颗；后续失去顶部支撑的球正常掉落 |
| specials | 20% | 分散转化 2–5 颗既有普通系统球为炸弹，数量均匀；优先最大间距，不移动、不改颜色、不新造库存 |
| ammo | 20% | 免费赠送 3–5 颗可用球，整数均匀，写入同一赠球总账 |
| dual | 8% | 授予一发双彩助攻，沿用既有双彩匹配和退款规则 |
| fullClear | 2% | 真正移除当前屏幕所有球；正常出票、三星收集、库存回收，短暂空场后使用既有顶部入场机制 |

权重是可试玩的原型参数，不代表最终经营参数；集中在 pet-slots.mjs 的 SLOT_REWARDS，可后续设计后台参数配置和受控版本迁移。不要在客户端展示概率或把本次当成经营赔率完成版。

所有不可达结果在开始时就转换成明确的 12 张彩票：特殊球普通系统库存少于完整批数、没有至少两个相邻闪电目标、清屏盘面为空、双彩无另一颜色或旧双彩权益尚未使用。pending 记录 fallbackFrom / fallbackReason，演出与结算只读取最终 rewardType，不先显示一种奖再临时替换。特殊球不会因为目标不足缩水。

## 随机与账务

petSlots.rng 为独立持久化 LCG 流，初始化 s.rng XOR 0x8bc4a617，递推 seed = (seed * 1664525 + 1013904223) mod 2^32；不使用主盘面 RNG 抽奖。满格事务一次固定 spinId、结果、数量、目标 ID、闪电真实边、双彩配色。整个旋转期间这些目标不能被其他球盘推进修改。

spinId 形式 pet-spin-N 单调递增。开始和结束均走 EndlessGame.tx：先 clone 草稿，执行，验证所有守恒，再 save，最后发布带 eventId 的事件。写盘失败不发布已中奖事件，不消费内存结果；从持久化状态恢复后只能兑现原结果。

彩票奖励使用 spinId: tickets 或 spinId: clear 去重；赠球使用 spinId: ammo 作为已有 ammoBonus.rewards 下的新 source=petSlots 记录，赠球总账校验同时认可 3–5 颗老虎机奖与旧大消除赠球。清除与掉落仍调用 collectStage、harvestLowOpportunity、creditHarvest、endNetwork / updateNetwork。三星完整集齐继续给原 stage 固定奖励并开始下一阶段。中奖清除不再次调用连消、蓄力或大消除赠球，避免奖励递归。

全清后的系统球变成已有 credit，不新造免费系统库存；空场恢复采用 evolve / ceiling wave 机制，奖励结算本帧不机械填满。闪电只有随机真实邻接清除，不凭空跨空格，不要求球本身是导电球；对应 networkPropagated 的 steps 可直接绘制。

## 接口

snapshot.combo = { streak, tier, lastShotId }。
snapshot.petSlots = { mode: slots | legacy, charge, threshold: 3, state: charging | spinning, sequence, spinId, remaining, pending, lastResult, lastChargedShotId, rng }。

- comboChanged: { shotId, streak, tier, previousTier, ended }。
- petChargeChanged: { shotId, before, after, threshold:3, sourcePoints }；结算归零增加 reason:resolved。
- petSlotStarted: { spinId, rewardType, label, count, duration:2.6, targetIds?, electricPaths?, secondaryColor?, fallbackFrom?, fallbackReason? }。
- petSlotResolved: 开始字段加 { actualTicketDelta, actualAmmoDelta, removed:ball[], direct:ball[], dropped:ball[], added:ball[], electricPaths:edge[] }。

removed 包含真实直接移除和掉落，added 是原球转为炸弹后的副本，不是新球。electricPaths = [{ fromId,toId,from:{x,y},to:{x,y} }]。闪电同时有 networkPropagated 事件，表现层避免对同一结果重复播放。

中奖中的 targetsCollected / stageBonusEarned 额外标记 shotId:spinId、rewardSource:petSlots，ProgressBridge继续处理进度，普通按射击聚合的视觉队列可以过滤它们，最终统一由 petSlotResolved.actualTicketDelta 播放奖励飞行。

模式为新增 constructor petSlotsEnabled=true；只用于首次创建/从无 petSlots 字段旧存档升级。已持久化 petSlots.mode 优先，恢复不会因默认参数改变模式。旧 mechanics 双彩回归测试显式 false 验证旧路径。

## 文件责任

- core/combo.mjs：初始化、逐射击连消更新与校验。
- core/pet-slots.mjs：三格、独立抽奖流、持久化预存结果、计时和奖项结算。
- core/settlement.mjs：原付费落地结算结束时推进连消与三格。
- core/core.mjs：加载迁移、旋转期间发射锁与波冻结、snapshot。
- core/ammo-bonus.mjs：沿用总账新增老虎机赠球来源。
- core/state-validation.mjs：新增字段校验纳入原事务。

## 验收

新增 pet-slots.test.mjs 13 项：六种奖实际兑现、库存/赠球守恒；开奖恢复、固定结果、幂等；不可达 fallback；连续消除、重复射击、退款与蓄力保留；抽奖开始写盘失败；旧 charge / ready 权益兼容；真实轨迹三次成功触发；开奖写盘失败后恢复一次。历史 density 账务统计补计 petSlotResolved.actualTicketDelta；历史 mechanics 明确 legacy 模式；旧 special 500 发旧炸弹上限回归也明确 legacy 模式。

本交付尚未包含视觉转轮、语音、音乐、客户端文案及公网部署，这些由对应Agent和主Agent整合。最终节奏和权重仍需真实试玩调整；当前奖励算法属于原型本地逻辑，未加入服务器抽奖或生产机台实物接口。
