# 协作与接手规范

## 日常规则

主对话保持产品决策、版本集成和验收入口。所有后续代码进入game/，不要再复制demo-v16、demo-v17形成新的维护主线。历史archive是参考和回滚材料，修改它不会自动进入当前游戏。

每次迭代用明确版本/变更记录和发布包区分。建议引入Git分支、tag与PR，但当前工作区未初始化Git，此次没有创建远程仓库或提交。

## 修改范围

核心Agent负责core及数值模拟，不写画面、不生成伪中奖记录。表现Agent负责presentation、feedback、assets与提示，不改奖池、余额或物理。集成人员负责app、启动、存档迁移、接口契约和端到端检查。

共享坐标、事件字段或配置需要先说明影响，避免两边同时改同一文件。只有真实已提交事件才能播奖励；效果类不直接调用earn、coin或confirmDispense。每个特效要有causeId/shotId以及生命周期清理。

## 交付格式

每个任务说明问题、目标、修改范围、接口、验收方法。交付时列出：修改文件、行为变化、数据迁移是否需要、已跑检查与证据、未完成项、兼容性与集成入口。

涉及奖励变化时附同种子前后对比、各操作策略分布、账务校验及长尾数据。涉及视觉时附免费/付费/补球/连锁/领奖/故障画面与窄屏检查，说明性能资源变化。

不要通过“看到效果不错”代替账务验收；也不要因为核心测试通过就宣称实物出票成功或Android性能已达标。

## 常见接手问题

1. 先阅读README、02结构、03玩法、04账务，启动4210验证当前样子。
2. 修改后运行tools/check；核心变化再运行全部tests/core。
3. 修改特效或资源后运行浏览器检查，确认32项声音完整和提示无遮挡。
4. 查看output/verification当前证据，不把archive里旧报告当作新版本通过。
5. 切换规则配置前，确认旧存档与余额迁移方式；保留待出票而不是重置它。

工具链目录包含package-lock，禁止用“安装最新版”作为常规迭代步骤。资源和引擎升级应单独测试，不能与玩法回报改动捆在同一次发布里。
