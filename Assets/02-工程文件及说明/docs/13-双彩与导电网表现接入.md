## 文件及运行入口

全部为新增文件。`game/src/feedback/assist-network/`：

- `art.mjs`：沿用原球图集的双色半球、三格宝石、导电符号和细连接。

## 视觉行为

三格是原萌宠项圈上的小宝石，不新增长期HUD。成功蓄能由真实清除位置向项圈飞入，准备与发射通过原drawDragon的连续肩颈姿态绘制。就绪小提示位于炮台上方，已在截图检查后避开炮口和下一球。两半都采样原orbs-refined图集，保留明确主/副色；null或同色副色按单色处理，显示“下一发单色助攻”，不伪造双色。

静态导电符号是开口菱形与分叉线，不像星球或炸弹；不改球主色。连接由实际边决定，用真实渲染位置随盘面移动。命中后，匹配颜色各自短路径→起点冲击→按steps沿边通电→节点收缩碎片。bombContacts只画提供的真实节点到炸弹交接，原炸弹爆破仍交原系统负责。掉落节点不画电流。

双彩与电节点共享ID时，节点退场只交导电层负责一次；共享弹丸只绘制一次退场。仅蓝色成立不画绿色成功；失败只保留原主色附着，没有准备或成功庆祝。所有飞票仍应来自原奖励通道，新模块从不发票或记奖。

宝箱/故障/收星占优时传priorityBusy=true，暂停新助攻提示、延后就绪cue并保留原宠物姿态。恢复快照直接显示格数、双色及节点，不重播准备、通电或领奖。减少动态取消能量长途飞行、碎片和宠物小跳，保留明确双色、三格、静态连接及短程电线/退场，不用全屏闪白。

## 主对话最小接入点

1. 初始化时导入`createMechanismFeedback`，使用现有atlas，创建一个实例；`restore(snapshot,{eventSequence:cursor})`与原feedback.restore同次执行。
2. 原drain的真实已提交batch先交`mechanisms.consume(batch,s)`，再交旧feedback消费。每帧使用原elapsed调用update，传uiPaused、reduced与priorityBusy。不要另开RAF。
3. 为旧EffectsUI增加一个可选的**视觉退场过滤及时间计划**：在flush拿`mechanisms.retirementPlan(shotId)`。保留原direct、dropped、gain、targets、奖励飞票数据；仅通用绘制数组排除plan.directIds/plan.electricIds。不能把整笔paidShotResolved丢掉，也不能修改奖励数组后算票。电流节点、匹配球交新层；炸弹triggers及其他直接球仍交旧层。按plan.dropDelay延后该发掉落/目标到达，延长该发视觉life，确保旧掉落不在导电之前完成。原飞票建议接在该发退场叙事之后，票数仍来自原gain/bonus。
4. 在原EffectsUI画完后，调用`mechanisms.draw(feedback.ctx,models)`，不另clearRect。静态节点位置用scene.boardPoint对应同ID实际渲染位置；alivePoints传全盘当前渲染中心，避免旧碎片盖住新补球。若相机root平移，使用同一渲染坐标系（现有scene.renderedPoint或宿主统一转换），不能只移动球不移动标记。
5. 双色覆盖层需要和原球mesh互斥。每帧先调用`restoreOrbVisibility()`，再运行原sync/tick装填逻辑，避免上一帧隐藏的transfer一直不可见。`sceneOrbModels(scene,s)`会优先选真实loadTransfer球，否则选择loaded，projectile选原实际mesh；使用其中心、半径、visible。draw返回后调用`applyOrbVisibility(models,painted)`只隐藏已经覆盖的对应mesh。关闭特效或dispose自动恢复本模块隐藏的原mesh。装填中优先绘制真实transfer，不能同时绘制静止loaded。免费projectile没有assist字段，不绘制双色。
6. 为createBabylonPet增加可选poseModifier，在原drawDragon之前用`mechanisms.petPose(f.pose,{busy})`。busy至少覆盖target、complete、fault等高优先级原反应；不替换原controller、不再绘制第二只宠物。项圈锚点随原step/hop及呼吸移动，默认x144/y1429。
7. pagehide/dispose调用mechanisms.dispose。不要修改存档、schemaVersion或storage keys。

示例骨架（只是接入说明，未修改正式app）：

```js
const mechanisms = createMechanismFeedback({atlas, onCue: existingCueRouter});
mechanisms.restore(s, {eventSequence: cursor});
mechanisms.restoreOrbVisibility(); // 每帧，在原scene.sync/tick之前
mechanisms.consume(batch, s);
mechanisms.update(elapsed, {paused: uiPaused, reduced: r.reduced, priorityBusy});
const models = sceneOrbModels(r, s);
const painted = mechanisms.draw(feedback.ctx, {
  loaded: models.loaded,
  projectile: models.projectile,
  nodePoint: n => actualRenderedPointForId(n.id),
  alivePoints: currentRenderedBoardPoints,
  collar: currentPetCollarPoint,
  priorityBusy,
});
mechanisms.applyOrbVisibility(models, painted);
```

`director.claimedIds`是当前演出的临时集合；`retirementPlan(shotId)`是同发接入计划。原画面中通用消除、炸弹和补球有各自遮罩，集成时要在绘制职责上排重，不能只叠加新画布。本轮未越过共享文件边界擅自做这一步。

## 声音与降级

只发`assist-charge`、`assist-ready`、`assist-fire`、`mechanism-impact`语义cue，不创建音频上下文或新音频资源。建议主对话先复用现有轻蓄能/短角色音及一次chain冲击；charge弱、ready中、fire中，impact按intensity限强度。impact同一0.22秒窗口最多一次；主对话还需与同发原explosionResolved的声效/震动合并，避免两系统各打一遍。新模块本身没有相机震动及全屏闪光。

`setEnabled(false)`关闭新层并返回空退场所有权，保留快照；宿主恢复旧通用退场和单色mesh。减少动态走update的reduced参数，不改玩法。异常可关闭此层继续旧表现；未知新增接口版本跳过并记录warning，不推断匹配或网络。
