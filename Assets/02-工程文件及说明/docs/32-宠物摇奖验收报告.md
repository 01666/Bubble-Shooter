# 1.7.0 连消与宠物摇奖独立验收

验收日期：2026-10-13（北京时间）。范围：本地开发版本；未部署、未修改公网 1.6.1。

## 结论

本轮新增功能可交付本地体验。浏览器自动验收 11 个场景通过，未捕获页面运行错误或 console error。主集成最终 core/feedback 回归报告为 111/111 通过；验收 Agent 另外独立执行宠物摇奖核心单测 11/11 通过。

所有奖励都来自真实核心交易与持久化账本，不以播放动画作为“发奖成功”的证据。6 种奖励分别检查彩票账本、赠球账本、盘面或者双彩资格。截图已检查闪电、清屏、特殊球和零余球摇奖，不存在挡住发射器、顶部余额或被免费试射提示覆盖的问题。

## 方法与复现

在项目根目录执行：

```powershell
node game/tests/browser/pet-slots.cjs
node --test game/tests/core/pet-slots.test.mjs
```

浏览器测试自行建立 `127.0.0.1:4251` 临时服务，并在 finally 中关闭自己建立的浏览器与服务。原有游戏服务保持运行。测试使用独立浏览器上下文，不覆盖用户实际试玩存档。

每个奖励 fixture 都由 `EndlessGame` 的真实 `startPetSlot` 随机抽取并在完整事务提交后保存。只搜索种子选择需要覆盖的分支，不修改开奖结果，不在 UI 中模拟发奖。浏览器从真实 spinning 存档恢复，经过核心 2.6 秒倒计时真正开奖。

连续三次成功消除场景：前两次通过核心真实瞄准、发射、飞行和落点结算得到 2 格蓄力，第三次在浏览器通过实际核心发射完成，观察 started/resolved 事件和连消 3 次。没有直接把 charge 改为 3 来替代该场景。

受运行环境网络沙箱限制，首次访问 localhost 返回 `ERR_NETWORK_ACCESS_DENIED`。经针对性的本地浏览器执行审批后正常验证；未改浏览器安全设置、未访问生产服务器。

## 实测结果

| 场景 | 核验结果 |
| --- | --- |
| 真实付费连续消除 | 第三次成功消除触发 `petSlotStarted`，核心倒计时后触发 `petSlotResolved`；combo 为 3 |
| 真实附着但未消除 | combo 归零；已有 2 格宠物蓄力保留 |
| 免费试射 | 不增加 combo 或宠物蓄力 |
| 彩票奖励 | 实际增加 12 张；12 个奖励单位飞行、12 次到达；刷新无重复 |
| 连锁闪电 | 实际消除 6 颗、增加 6 张；存在真实沿线闪电，6 个奖励单位飞行；刷新无重复 |
| 特殊泡泡 | 实际将已有 4 颗系统球改成炸弹，盘面球数不变；保持球 ID、颜色及库存；刷新无重复 |
| 赠送泡泡 | 可发射数实际 +5；赠球账本 +5；刷新无重复 |
| 双彩助攻 | 核心 assist 成为 ready，而不是只显示双彩字样；刷新保留资格 |
| 全屏消除 | 实际清除 72 颗；本 fixture 产生 80 张（包括收集完星星后的阶段奖励）；80 个奖励单位飞行、80 次到达；不额外产生大消除赠球 |
| 无可执行目标的保底 | 空盘抽到双彩时在动画开始前转换为 12 张彩票，并实际结算 |
| 暂停、静音、减少动态、刷新 | 暂停时 remaining 连续 500 ms 不变；静音 disabled 和 reduced 状态实测为真；刷新恢复同一个 spinId 和预存结果，只增加一次赠球 |
| 0 颗可发射球 | 摇奖仍正常显示及结算；免费试射提示不遮挡老虎机；余球维持 0 |

其中 miss/free 归为一个自动场景，暂停/静音/减少动态/刷新归为一个自动场景，因此报告的场景数为 11。

每一种开奖都重新创建 `EndlessGame` 读取实际持久化存档，执行全部核心校验，覆盖彩票、赠球、付费球和系统库存守恒。兑奖清屏与闪电不会递归增加宠物蓄力或 combo，也不会按照“大消除”再赠球。

### HUD 核对

不能只断言核心 earned 增加。本次还等待 `RewardFlights.queued=0`、`flying=0`，核对 scene.displayedPending 与真实 tickets.pending 相同。

全屏奖励的实测终值为显示 37、实际 37。普通彩票及闪电场景在等待结束前已被模拟设备吐完，因此终值都为 0；它们的飞行单位及到达次数仍分别完整为 12、6。

这项验证覆盖“有真实奖励但右上角永远停在旧数字”的风险，也验证包含阶段奖励的清屏收益只飞一次。

## 老存档验证

除新增核心单测之外，独立读取冻结 1.6.0 的真实核心实现，建立旧版 ready 和 inFlight 双彩存档，再交给新核心加载。

- ready：保留双彩 ready、10 颗可发射球，进入新的 slots 模式。
- inFlight：实际旧版先发射、推进 0.25 秒，再在飞行中恢复；保留 assist-1、9 颗可发射球；恢复后继续实际飞行结算，触发 dualMatchResolved、付费发射计数为 1、通过完整核心校验。
- 本项是核心存档与实际飞行恢复验证，未声称旧存档浏览器 UI 迁移或物理断电验证。
- 新核心单测另外覆盖旧 charging 蓄力转移和已持久化 legacy 模式保持。

冻结 1.6.0 与 1.6.1 的相关配置和老存档模式兼容；测试没有直接修改冻结版本文件。

## 仍需要产品体验判断的事项

1. 当前连消升级是表现层升级，没有另加可叠乘的彩票倍率。宠物蓄力按累计成功消除，与“必须连续成功”的 combo 分开，未消除只清 combo。这一点需要在玩法说明持续保持清楚。
2. 摇奖暂停发射约 2.6 秒，开奖面板再留约 1.65 秒。需要用户实际体验这个节奏是否偏慢；自动测试只能确认正确性。
3. 当前结果权重和奖励数属于原型方案。本次没有进行长期收益率、波动、免费赠球循环经济或运营赔率验收。
4. 静音和减少动态验证的是浏览器状态和核心不受影响；没有真人听音验收，更未完成音响设备或安卓板性能验收。
5. 特殊球优先选择空隙最大的现有系统普通球；密集盘面或大量特殊球情况下无法承诺所有球之间始终达到固定间距。本次验证样例分散，不将其夸大为任何盘面都绝不相邻。
6. 使用 browser localStorage 的保存不等价于机台断电的生产级原子存储。实际出票仍是模拟设备；服务器版本仍为既有 1.6.1。
