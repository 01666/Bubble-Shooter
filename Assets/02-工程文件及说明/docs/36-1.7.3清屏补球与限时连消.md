# 1.7.3：清屏补球修复与限时连消

当前本地试玩：http://127.0.0.1:4210/?v=1.7.3 。公网仍为1.6.1。本说明覆盖旧版“失误不清宠物蓄力、无时间限制”的规则，其他开奖、并行发射、语音和装置继续沿用1.7.2。

## 清屏后的盘面恢复

问题来自全屏消除前已经排队的浅补球计划，例如recoveryWave仅两行。旧advanceFlow看到存在pending计划就不再安排完整空盘恢复，因此先补两行，后续低密度检查才一次补至七八行。

修改endless-flow.mjs：空盘时允许覆盖尚未提交的旧波次，改为emptyBoardWave、7或8排、1.45秒留白。之后同一次入场提交完整新盘面。普通消除仍采用原自然顶部推进、留白和压力节奏，不按消除数量机械回填。

不凭恢复多发奖励、也不额外增加系统库存：顶部新球仍使用reserve/credit预算，连通结构、颜色算法、特殊球入场和新球动效沿用。完整入场提交后原旧浅波次不再执行。

## 六秒连续消除蓄力

当前试验窗口为6秒，每次实际付费球成功消除（赠送的可用球同样走付费发射模式）增加一格并重置6秒。连续成功3次自动获得一次摇奖，每摇有奖。失误落地或窗口结束清空未完成进度和连消档位；已经获得的彩票、赠球、正在摇出的奖项和已经攒满三次的后续摇奖资格保留。

摇奖仍允许继续发射。期间成功消除计入下一轮；queuedCharge的完整三连次数属于已经获得的资格，打断只清除剩余1或2次的未完成进度，不能抹掉已完成资格。开奖本身造成的消除不递归推进蓄力。

免费试射不增加、不续时。退款不算失误、不续时；如果原窗口自然到期，仍按超时结束。投币不会重置时间，也不会凭投币增加连消。暂停及切后台通过原dt=0机制冻结倒计时，刷新恢复保存的剩余游戏时间，不重新给完整六秒。

机器强制顶部波次pending期间不扣窗口；真实补球提交后额外0.55秒入场宽限，覆盖画面移动暂时不允许发射的时间。窗口结束时已经发出的付费球保留判定资格，待其自然落地：成功则续时/蓄力，失误或退款结束后若已到期则断连。这样不会因球的飞行距离惩罚最后一刻正常出手。

## 左下角表达

装置上方直接显示“连消1/3 · 再消2次”、剩余秒数和时间条；摇奖期间显示“下一轮”，区别已经获奖的当前三连。最后2秒数字与时间条变暖色，没有频闪。无进度时提示“6秒内连续消除 / 满3连摇奖 · 必有奖”。

断连时短暂显示“时间到 · 连消重来”或“未消除 · 连消重来”。倒计时内已发出的球正在判定时显示“命中即可续连”。暂停时装置、进度和剩余时间仍显示，奖励大字避让暂停/异常提示。

## 工程结构与恢复

新增src/core/pet-chain.mjs，独立管理timer、失误、超时与获奖保护。petSlots增量字段chainVersion、chainWindow、chainRemaining、deadlineShotId、chainGrace，不修改存档键或配置身份。

旧存档首次升级时给已有未完成进度一个完整试验窗口，原已开奖/在摇奖/排队资格保留；此迁移只执行一次。之后刷新不重置倒计时。所有修改通过原核心事务保存后发布事件，界面仅读取计时和进度，无权私自增减奖额。

## 验证

130项核心/反馈测试通过，新增专项覆盖超时清空不丢账务、免费及退款行为、已有奖项和完整排队三连保留、暂停/刷新、强制补球宽限、最后一刻出手、旧两行计划被清屏覆盖。

浏览器实际复现“清屏前已有两行计划”并验证修复后的盘面数量序列为72→0→63，恢复7排且63颗在渲染层均可见，没有中间18颗阶段；新入场只有一个emptyBoardWave计划。另一场景确认5.7758秒暂停900毫秒后数值不变，正常命中第三次消除触发真实摇奖。无脚本错误。报告和截图：output/verification/v1.7.3。

6秒是体验用初值，后续可以基于正常瞄准耗时、成功续连率与玩家反馈调整。当前没有新增票倍率或修改老虎机奖项概率。
