# 1.8.0 工程结构、接手指南与封版验收

日期：2026-10-13。认可体验基线：1.7.3；昨天公网基线：1.6.1。本次是工程整理与文档统一，不改当前认可的玩法、数值、物理、素材或存档键。

## 2. 本次具体整理

1. 原core/pet-slots.mjs同时承担初始化、抽奖、目标、结算和校验，拆出五个职责模块；原文件保留稳定入口及状态编排，外部导入路径不变。
2. 原PetSlotFeedback混合事件调度与多种绘制，拆出machine/combo/effects；原类仍拥有时间、事件去重、暂停、声音与生命周期，保留原方法签名。删除没有调用的旧drawCharge对话框绘制，避免未来同时维护两套进度UI。
3. 真人配音配置独立为announcer-profiles；播放器仅加载、排队、选择和播放。旧导出继续从arcade-announcer再导出，调用方不变。
4. 全部src使用已安装Prettier统一格式，展开近期多语句紧凑代码，保持执行顺序。没有改RNG、权重、碰撞、奖励ID、事件顺序或延时。
5. 对照工具接受明确的1.7.3副本；增加六种摇奖/在途重载专项等价工具；纠正旧浏览器测试“失误保留蓄力”断言为实际六秒规则。浏览器测试总入口输出目录随版本变化。
6. 增加从冻结发布构建公共部署包的工具，校验源哈希，拒绝覆盖已有部署，白名单复制公开文件，生成公网SHA清单；HTTP UUID兼容只在部署副本加，不改冻结业务源。

没有搬动历史封版、清空机器余额、修改配置身份或把版本号升级当作存档重置。

## 3. 规则层职责与修改入口

| 模块 | 负责 | 修改时的边界 |
| --- | --- | --- |
| core/core | 唯一EndlessGame、事务、输入操作、推进与恢复 | 校验保存成功后才发布事件 |
| core/settlement | 一发paid吸附、匹配、机制、票/赠球、资格演进 | 保持因果顺序，不给同球重复奖励 |
| core/state-validation | 全状态不变量 | 和存档增量迁移同时审阅 |
| config / migration | 原型参数、配置兼容 | 修改持久配置需显式迁移政策 |
| geometry | 六邻、连续碰撞、吸附、预测 | 引导与真实发射共享算法 |
| board-colors | 生成色团/长条权重 | 不改旧球、玩家色、不暗改在途球 |
| board-policy / endless-flow | 库存、维护、自然顶部波次 | 108系统库存守恒，留白，不机械回填 |
| protection | 近期铺球及真实支撑 | 安全边界可覆盖保护 |
| special / special-placement | 三星宝箱、基础炸弹、分散、新行属性 | 事件前确定属性，不造额外库存 |
| mechanics | 双色匹配、资格、导电网络闭包 | 真实邻接、电击预算、ID去重 |
| low-opportunity | 购买额度、低余球申请、数量时机、分散 | 2–5整批，无总炸弹上限 |
| combo / pet-chain | 连消档位、六秒、失配/超时、临界出手 | 只清未满资格；暂停及强制波次保护 |
| pet-slots.mjs | 初始化、推进、排队与公开API | 不再混入渲染或具体奖励算法 |
| pet-slots/rewards | 权重、2.6秒、独立随机、12票兜底 | RNG调用顺序有验收约束 |
| pet-slots/plan | 开摇固定类型、数量、计划目标 | 开摇不先发奖励 |
| pet-slots/live-targets | 奖项对实时盘面重绑 | 不重抽类型数量，不在球飞行中改盘 |
| pet-slots/settlement | 一次已固定奖的真实落账/盘面效果 | 复用票、赠球、库存、宝箱协议 |
| pet-slots/validation | 摇奖字段和目标合法性 | 校验允许计划目标在转动期被真实发射消除 |
| ledger / ammo-bonus | 彩票义务与赠球唯一账 | 动画没有落账权限 |
| storage / simulator | 存储适配、模拟出票反馈 | 真硬件未来换适配器，不改奖励公式 |

建议看一发执行链：core.fire→geometry.flight→core/settlement→匹配/导电/炸弹→ledger及ammo-bonus→board-policy→宝箱/网络/预览→combo→低余球→pet-slots。摇奖链为pet-chain/tick→pet-slots→live-targets→settlement→结果事件；整个过程都在原事务里。

## 4. 表现层职责

client/app拥有唯一RAF、核心实例、设备及输入；presentation-upgrade统一音画升级消费顺序和退场归属。presentation/scene、scene-base、sprite-layer负责Babylon渲染基础与器具，guide负责珍珠预测线。sprite-layer的Region/着色器仍被继承使用，保留兼容基础类，不误删整个文件。

feedback/effects-ui管理普通发射/吸附/消除/掉落与飞票；reward-counter管理动画显示余额，业务余额不由它决定。mechanisms负责真实双彩/导电路径，orbs负责材质/标记/特殊登场，environment负责动态房间。pet负责小龙动作与原生整体绘制，pet-slots/layout集中宠物与机器坐标、拉杆握点。设备移动时要改共享layout及宝箱端点，不能各层随意偏移。

pet-slots/feedback是调度器；machine绘制常驻装置、时间进度和结果爆字；combo绘制升级字；effects绘制开奖结果目标电弧/冲击圈。绘制函数使用同一个feedback实例上下文，仅读状态，不更改业务。它们调用drawPrizeBurst共享街机中奖样式。保持类方法包装以兼容现有测试及调用方。

audio/audio拥有唯一AudioContext与BGM/SFX/voice总线；score-tick为逐票短音，arcade-announcer负责已授权真人短句选择/去重/冷却，announcer-profiles只描述四语义档与女声A/B、男声/关文件。rewards/reward-voice仍负责旧语义短句/字幕调度；二者共享voiceSource及duck避免抢声。license见assets/licenses/arcade-announcer.txt。

## 5. 数据、事件与协作契约

- 机器键bubble-integrated-v15-machine；模拟设备键bubble-integrated-v15-device；配音偏好另存bubble-arcade-announcer-choice。保留schema1及experimental-special-v4-1配置身份。
- 1.6.1旧存档增量初始化combo/petSlots/六秒窗口，旧双彩已ready/inFlight保留；1.7.3存档不再重新迁移。不得通过localStorage.clear观察新盘面。
- 票账、赠球账和系统库存各有唯一不变量；同一奖励不同演出层共享因果ID，不建立第二套收益。
- 核心提交事件后，表现按快照消费；网络、开奖和飞票均不得通过“动画完成”给奖。
- 加机制先定义成功条件、资格、奖量、存档字段及事件，再由美术/声音实现已提交结果；禁止规则与美术各自抽奖。
- 添加新奖项至少补计划、实时目标、结算、校验、图标、台词语义、恢复和真实浏览器验收，不能只加rewards数组。

## 8. 发布和部署

先检查并验收，再运行`tools/package-release.ps1 -Version 1.8.0 -BaselineVersion 1.7.3`，禁止覆盖已有冻结。产物包含game、docs、README及启动器，不含node_modules、archive、output和SSH密钥。manifest记录逐文件SHA及大小；check-release复查。后续新改动用新版本，1.8.0不可边测边改。

`node tools/prepare-deployment.mjs 1.8.0`只从冻结源构建site，白名单为index/style/src/assets/vendor，加部署版本信息、HTTP UUID兼容及公网文件哈希。公开目录不放源码测试、工具、完整文档、私钥或机器存档。HTTP兼容用getRandomValues生成RFC4122 UUID，仅解决IP HTTP下randomUUID接口缺失。

服务器Ubuntu22.04/Nginx80，站点current切到`/var/www/bubble-arcade/releases/1.8.0-http/site`，旧1.6.1-http和1.6.0-http保留。上传后先在新目录sha256sum校验，再记录旧current，最后切换symlink；配置不变，无需重启其他服务。回退只将current指回记录的旧site，不清同事浏览器存储。正式公开试玩链接为http://8.134.94.47/?v=1.8.0，HTTPS未配置。

同事各自浏览器是独立公共机器；公网并未新增中央账务/账户服务，投币与逐张出票仍模拟。部署后检查版本信息、资源MIME、非安全上下文投币、实际发射、女声加载、刷新以及1.6.1存档迁移，另存部署验收记录，不改冻结包。
