# 1.3.2 实际盘面与动态修正

用户连续游玩发现盘面偏稀、动态不明显、低余球经常没有新特殊球。本轮直接检查了当前应用内浏览器：页面加载的旧模块没有新的固定机制说明，盘面仍为约21颗；重新加载后说明和晶核已进入画面，但盘面扩容仍等待下一次付费结算。上一轮新建机台测试不足以代表这个旧存档体验。

## 盘面

常态目标八排、72颗。密集策略不再使用旧pockets策略的openCorridor四排边界。每24次净付费结算中的第18–21次采用十二排球潮目标108颗，约占六分之一的时段；结束后按原保护规则维护，近期玩家铺球仍可暂时保留。该原型节奏可后续调整，当前不是商业数值方案。

新增densityBaseRows=8、densityPeakRows=12；保留旧densityTarget字段作为数量下限，实际目标取下限与当期行数容量的较大者。密度内容预算为108，未显示的预算留在暂存或生成额度，三者仍守恒。densityVersion=2使旧版本一次性升级；无在飞弹丸的旧机台进入页面立即补足，不再等待投币或射击。有在飞弹丸时留待该发结算，避免刷新改变既定飞行盘面。保留旧球ID、颜色、已购余球、星星进度和彩票账务；入场补充不发奖，也不重抽旧球。

常态八排球群的外包矩形视觉占幅33.49%，十二排球潮50.06%。这是球群边界，不是不透明圆形像素面积之和。消除、掉落和入场过程可暂时较空，演出结束后补齐。十二排仍高于炮台安全线；安全维护和库存恢复保留。

## 动态显示

普通球增加跨越中部的移动反射带，避免只在原图本来已接近白色的高光区域叠加亮度而几乎不可见。呼吸幅度从1.2%增至3.5%，频率提高。特殊球增加呼吸光晕、各晶面的流动亮面，以及更亮更快的绕球光点。导电晶核继续沿真实网络绘制，不编造连线。

材质诊断增加applied计数，检查着色器确实替换原材质，而不只检查已创建多少个对象。浏览器从真实WebGL画面取64×64球体区域，对比间隔1.1秒的像素，最后一次回归实测平均绝对通道变化18.50，确认有可见像素变化。减少动态模式仍可关闭这些持续运动。

## 低余球

实际特殊球登场不再播“最后两球有爆破/奖励”的说明。付费结算剩两球或一球时只显示余球提醒与“投币可补充泡泡，继续游玩”，无奖励承诺。特殊球自身仍有登场光环和持续动态，正常消除后的真实获票反馈保留。

lowOpportunityBombLimit新增默认12，可配置2–18；旧默认四颗的上限已过于容易被上一轮未消除球占满。申请次数和净消耗间隔仍保留，一次申请最多两颗真实爆破球；选择范围扩展到球潮的安全前沿。未触发、不满足购买额度或没有可用球时不伪造特殊球。没有改变颜色匹配规则、发射弹道或中奖记账。

同一种子120发主动消除：12次申请，12次登场，共24颗；120发随机射击：12次申请，8次登场，共14颗。随机策略仍可能因预算已满或无可用前沿球而跳过，不能宣称每次最后两球必有新增。此处只报告该原型样本，不代表真实续币率或商业回报。

## 验证

核心与反馈70项通过，覆盖旧存档进入即补齐、球潮容量、守恒、特殊球去重和余球提示不泄露奖励规则。六组浏览器回归分别覆盖原投币/账务、装填、宝箱、移盘、复合机制、密集球潮。

密集盘面独立浏览器26次真实键盘射击：72–109颗；1467帧未异常隐藏或缩放；72颗以上真实材质替换、球体像素变化和十二排超半屏占幅通过。报告和截图在output/verification/v1.3.2/。与上一轮相比不再只依靠新建机台或对象数量判断效果是否已展示。

版本1.3.2，默认地址和存储key不变。旧1.3.1发布包及其文档保留为历史记录。库存和爆破预算变化仍需在后续商业数值阶段重新模拟总出票，不沿用旧版统计。
