## 已冻结的业务语义

普通有效付费三消每发蓄1格，3格后下一付费球自动使用双彩；双彩发不蓄，免费冻结。主色来自当前球；副色在蓄满结算后从可见盘面其他色等概率抽取，独立持久随机流。单色盘面准备资格的副色为null，下一发明确按单色使用，不临时改碰撞、不命中时抽色。免费换主色可能与已定副色相同，此时只有一次单色匹配；资格和副色不重抽。失败留普通主色玩家球。无落点退球并恢复同一资格。

两色各自满足原三消后取并集；炸弹与导电互触发，在结算前同一盘面图上求闭包，然后统一移除、脱顶、收星与奖项。导电只沿同networkId的真实六邻连接；炸弹碰到节点可通电，激活节点可点燃真实六邻的炸弹；除此之外电流不清无关普通邻球。仅掉落不激活。每球一次计奖、回收及收星。没有额外助攻/电流奖。

导电最多3节点（盘面＋暂存总量），使用未标记系统球，不与target/bomb叠加。新机器创建初始网络时从快照恢复，不发送未事务提交的初始化事件；旧存档加载不新增节点，第一次真实付费补球可尝试建立首网。之后只在合法附着的付费射击实际补充新系统球时尝试创建，距离上次创建至少3次实际补充，距离最后激活或网络被收获结束至少2个已结算付费尝试；现有网络未全部离开盘面及暂存时不另建或补满。候选至少2颗真实相邻球，否则等待。无落点退款不得创建网络。维护只更新真实连接，不产生新标记、奖励或重新抽色。

## 坐标及标识

沿用事件 `{type,payload,causeId,eventId,revision,configVersion}`。新增业务事件payload都包含interfaceVersion:1。ball字段为 `{id,r,c,x,y,color,source,kind,networkId?}`；x/y是玩法逻辑坐标（上正下负），不是CSS像素或Babylon世界坐标。表现层使用现有逻辑坐标转换；路径端点为实际球中心。id沿用bubble-N；networkId为network-N，boostId为assist-N，序号持久保存。稳定ID用于去重，数组顺序只用于演出。

## 快照

新增 `snapshot.mechanicsVersion=1`。

`snapshot.assist={charge,threshold,state,boostId,secondaryColor,primaryColor,enabled}`，state为charging/ready/inFlight。ready期间primaryColor跟随当前装填色，secondaryColor固定；副色null明确表示单色准备。inFlight主副色以projectile为准。`projectile.assist={boostId,primaryColor,secondaryColor}`只用于付费球，普通/免费无此字段。

`snapshot.network={id,nodes,edges,reserveNodeIds,enabled}`。nodes是当前盘面节点的完整球投影；edges为 `{id,fromId,toId,from:{x,y},to:{x,y}}`，仅同网络的真实邻接；边id由两个球ID排序生成。暂存节点不画连接，身份保留，归位后依据新实际坐标更新。网络可能暂时只有一个可见节点或零可见节点，不暗连到暂存区。

## 同发事件顺序

接受付费球时，原shotAccepted之后可发assistShotAccepted。结算依次是dualMatchResolved（仅助攻）→导电激活/传播→原explosionResolved→networkEnded（节点全部被收获时）→原targetsCollected及stageBonusEarned/ticketsEarned→原paidShotResolved→维护/补球事件→networkCreated/networkUpdated→原previewLoaded→assistChargeChanged及assistReady或assistConsumed/assistRefunded。

所有事件在同一事务持久提交后才交付，顺序是表现契约，不表示多次业务计奖。电与炸弹的交叉因果以传播steps明确记录，不要求表现通过事件先后猜测。故障时不播放未提交事件。原奖励事件不重复发射。

## 事件字段

| type | payload核心字段及语义 |
|---|---|
| assistChargeChanged | shotId,before,after,threshold；只在普通付费成功实际变化时发送，失败/免费不发 |
| assistReady | boostId,primaryColor,secondaryColor,charge,threshold；一次资格创建，只在提交后展示，null副色不假画另一色 |
| assistShotAccepted | shotId,boostId,primaryColor,secondaryColor,shot；shot包含真实初始坐标和速度 |
| dualMatchResolved | shotId,boostId,primaryColor,secondaryColor,groups:[{color,size,matched,ids}],matchedColors,removedIds,attached；两个组共享弹丸但removedIds去重；均失败为空 |
| assistConsumed | shotId,boostId,result:clear/attached；已合法附着，用尽资格，本发不蓄 |
| assistRefunded | shotId,boostId,primaryColor,secondaryColor；无落点后恢复同资格，与shotRefunded对应，不重抽 |
| networkCreated | network完整投影，reason:paidRefill；新机器初始网直接读快照，不是奖项 |
| networkUpdated | network完整投影，reason:settlement/maintenance；连接以此替换，不自行推断暂存边 |
| networkActivated | shotId,networkId,seeds:[ball]；真正进入清除闭包的节点，不含仅掉落节点 |
| networkPropagated | shotId,networkId,seeds,activatedNodes:[ball],steps:[{fromId,toId,from,to}],bombContacts:[{fromId,toId,from,to}],edges；steps为实际节点传播，bombContacts为节点点燃邻接炸弹；坐标来自结算前盘面 |
| networkEnded | shotId,networkId,reason:harvested；全部节点实际直接/掉落离开库存，旧网不再绘制 |

原explosionResolved继续提供真实炸弹triggers与最终direct闭包；paidShotResolved新增 `assist,matchedColors,electricIds`（原direct/dropped/gain/bonus保留）。基础票按最终direct/dropped，不按steps或triggers另计。

## 低余球机会与真实反馈扩展

扩展接口版本2，开发中。原v1事件及字段继续可用，助攻/导电语义不变。新事件使用interfaceVersion:2；旧事件只添加可选字段，不删除或改名。背景、语音和奖励文字只消费已提交事件，不由核心调度声音/动画。

### 最小机制与资格

沿用现有炸弹：把一颗合格普通系统球标成bomb，保留ID、颜色、位置和来源，不增加总球数、不新开奖、不单独加奖。盘面加暂存中的炸弹仍最多2颗。不覆盖星、导电、其他炸弹、玩家球及近期铺路保护路径。只在合法付费附着结算、维护、装填和原特殊标记完成后申请。

实际可用的余额为1或2时进入低余球过程，一过程最多申请一次。额度间隔为Q=max(3,ballsPerCoin)：每Q颗真实购得球信用最多资助一次申请，首次还须净消耗Q−2颗有效付费球；一次申请后至少再净消耗Q颗才能申请下一次。不累计可补刷的消耗间隔；批量投币不会把阈值附近反复充值变成多次机会。默认Q=10，首次最多在第8个有效消耗后申请。退款不计净消耗；每次申请即占额度，即使最终因无候选跳过也不返还供重抽。

优先选择当前球（包括已准备助攻副色）可真实消除到的普通系统球；余额2时其次允许可见下一球在当前布局有真实消除路线的候选。真实轨迹和消除预测提供可利用证据，后续一发可能改变布局，不保证成功。候选须位于压力行以上及安全线之内，不修改弹道或搬走遮挡。选择按当前/预览优先级、深度和稳定ID确定，不新增随机抽样，不消耗任何现有随机流。

没有候选或现有炸弹已达上限时，保存同一申请，等下一次合法付费结算且仍有1–2球再检查；不每帧/免费/刷新重试。球耗尽或补币离开低余球区时跳过未登场的申请，额度已用。已经登场的炸弹不因补币、换人、归零、整理或刷新消失；暂存时不收获，归位后沿用原标记。下一次机会仍须满足新的消耗间隔和购买额度。

### 快照与新事件

新增snapshot.lowOpportunity，包含enabled、version:2、interval、fundedSlots、usedSlots、consumed、nextEligibleConsumed、episodeActive、episodeQualified、pending、last、targets。episodeQualified只在本次低余球过程实际申请后锁定，若2球时尚未满足间隔，1球时仍可检查资格；一旦申请则不再重复。pending/last记录opportunityId、requestedShotId、status、remainingAtQualification、remainingAmmo、reason、ballId、specialType。targets是盘面及暂存中已登场机会球的实际投影及location:board/reserve，用于公共继承和恢复，不重播登场声音。last代表最近一次申请，不是个人奖项或全部历史；较早机会球仍在targets中。

|---|---|
| lowOpportunityQualified | opportunityId、shotId、remainingAmmo、interval、usedSlots、nextEligibleConsumed、specialType:bomb；真实有效消耗后的单次申请，不代表已登场或获票 |
| lowOpportunityAppeared | opportunityId、shotId、remainingAmmo、ballId、specialType:bomb、ball（实际逻辑坐标/颜色/来源）、access:current/preview；实际完成普通球标记后才发送 |
| lowOpportunityDeferred | opportunityId、shotId、remainingAmmo、specialType、reason:bombLimit/noUsableTarget；仅合法付费结算重新检查时，原因未变不重复发同提示 |
| lowOpportunityFinished | opportunityId、shotId或receiptId、remainingAmmo、ballId、specialType、status:consumed/skipped、reason:direct/drop/noPaidShots/replenished；收获或未登场申请结束，不是独立奖项 |

新登场事件位于原previewLoaded及助攻更新之后，所有业务仍在一次持久事务提交后交付。机会球实际被清除/掉落时，Finished先于原收星与奖励事件；后者独立承载真实彩票。coin只可能关闭尚未登场的申请，不创建目标。

### 复用真实反馈字段

原targetsCollected追加total、remainingTargets、award（当前固定宝箱奖）、targets（球投影）；原stageBonusEarned已有count就是本轮真实额外票，只有本次新增入账才发。原paidShotResolved追加directCount、dropCount、explosionCount、electricCount、earnedDelta（实际账务净增，正常为gain+bonus）、pendingTickets、remainingAmmo、stageId、stageAward、lowOpportunityIds（该发实际收获的机会ID）。gain仍只指基础票，bonus仍指本次新入账宝箱票，不把earnedDelta再发一次账务或飞票。

原assistChargeChanged追加实际清除起点sourcePoints及remainingAmmo；原assistReady保留主副色和资格，加remainingAmmo。原networkActivated/Propagated、explosionResolved已有完整球ID和坐标，加实际激活/触发数量。原dispenseConfirmed的delta、pending及evidence继续是成功证据；可用observedTotal做核对，不把发出命令或画面+1当确认。

准确文案：只在Appeared后按remainingAmmo说“最后两球，特殊泡泡登场”或“最后一球，特殊泡泡登场”。Qualified、Deferred、Skipped不得播这句，不得宣称下一发必中奖或再投必得。进度、清除、掉落、收星、宝箱奖、当发新增票和出票确认分别读取上述真实字段；不要因同发多事件累加重复票。开发完成后在下文补充结果及限制。

## 低余球扩展开发交付

状态：核心开发完成，等待主对话与美术整合，未认定正式版本验收。双彩助攻、导电、炸弹、掉落、星与明示宝箱均保留；未消除仍不扣助攻进度。没有新的彩票奖项、随机开奖、付费道具、倍数、登录或联网。

### 最终选择与边界

选择普通系统球转炸弹，是为了复用已有真实破坏范围、连锁、掉落和奖励闭包，不引入第四套开奖。保持总炸弹上限2、保护路径和真实可消除路线，优先真实性和安全性，接受没有候选时跳过。系统球库存、主颜色、几何位置、原轨迹及吸附均不变；没有为了“最后两球”强制建立三连、搬走遮挡或压入新球。

当前色可用优先于预览色；只剩1球不以不能使用的预览色作为登场依据。预览色路线基于当前盘面可达预测，中间一发仍可能改变布局，因此明确不保证最后一发成功。实际登场后身份和类型固定，不根据下一发结果改写。只有实际收获才进入原basic/stage奖项。

### 迁移与持久化

新增config.lowOpportunityEnabled=true，供开关对照；原价格、ballsPerCoin、正式config.version、schemaVersion、mechanicsVersion及package版本不变。低余球状态自有version=2，不让旧v1表现误以为助攻/导电字段改版。

没有lowOpportunity字段的旧存档，加载时只增加额度基线、净消耗基线、空申请及过程标记。未使用付费球及已经在途的付费球信用计入可资助余额；此前已经消耗的历史不会追授申请。加载不申请、不标球、不抽色；下一次有效付费消耗再按规则判断。已有余额、收币凭证、在途模式、助攻、导电、宝箱、随机流、ledger和设备证据保留。损坏状态或真正不兼容配置仍报错，不清存储重新开机。

申请、延期、标记及结束均与整发结算原子提交；保存失败不广播未提交登场。无落点退款净消耗为0，不申请也不重试旧申请；恢复后仍只退款一次。刷新仅恢复pending/last/targets，不重播登场或领奖。暂停和无币等待不会驱动该模块，出票只继续原确认核销。

未来每币球数采用新机配置已验证（包含1球/币），Q至少3，防止一颗信用就可重复申请。正在使用的机台改变ballsPerCoin仍必须经过原有显式资源配置迁移，不能仅改常量；本轮没有放宽那项保护。
